# 目标项目写作约定

仅在需要建立或整理团队文档规范、术语表或品牌覆盖规则时读取。已有约定优先复用；单次写作或润色只需遵守已有规则，不自动新增配置文件。

## 定位与组织

先读取目标项目适用的 `AGENTS.md`、术语表、品牌规范和同类文档。规则冲突时说明具体冲突，按用户指示及适用范围处理；不要把本技能的示例或其他项目偏好写成当前项目事实。

在目标项目已有规范位置维护约定；没有既有位置且任务需要新建时，可使用 `docs/writing-conventions.md`，从团队已有文档入口链接。不要为了让规则生效而修改无关的全局配置。

## 需要确认的内容

按实际需求选择以下信息，只记录已确认的规则，不创建空章节或填入推测：

| 内容 | 应记录的信息 |
| --- | --- |
| 适用范围 | 项目、文档类型、读者、地区和语言；子目录或载体的例外。 |
| 事实来源 | 产品能力、版本兼容性、SLA、价格和限制的维护位置；无法核实的内容如何标注。 |
| 首选术语 | 概念、首选写法、允许的别名和使用条件；区分显示名称与机器标识符。 |
| 产品与版本 | 官方名称、版本展示方式；路径、字段和枚举值不受正文排版规则影响。 |
| 语气与排版 | 是否使用第二人称、引号样式、留白、数字和地区日期格式。 |
| 内容组织 | 确有需要的入口页、API 或故障排查结构，不要求所有文档套用同一模板。 |
| 必须保留的内容 | 固定引用、法律文本、安全警告、兼容性和弃用说明。 |

## 应用边界

明确区分默认规则和已确认的项目覆盖项，保留覆盖项的适用范围及来源。未知项单独说明，不将示例术语、建议时限或默认模板升级为强制约定。

建立规范不等于授权重写全部文档、重命名文件或修改代码字面量；已有文档的统一工作按用户要求的范围执行。
